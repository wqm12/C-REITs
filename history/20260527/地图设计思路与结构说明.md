# 公募 REITs 地图设计思路与结构说明

更新日期：2026-05-27

## 1. 当前版本定位

当前版本是面向 GitHub Pages 公开访问的个人 C-REITs 地图网站版本。核心目标是让访问者直接打开 `https://wqm12.github.io/C-REITs/` 就能看到最新地图，不依赖额外运行 Python、不依赖外部 CDN，也不需要手动下载依赖。

本轮版本以 `reits_map.py` 为最新维护脚本，以 `REITs详细分布图_20260527.html` 为最新生成网页，并同步为 GitHub Pages 入口文件 `index.html`。本次数据来自 2026-05-27 更新后的 `REITs_location_updating.xlsx`，新增了易方达广西北投高速公路记录。

页面底部制作日期只展示到月份，由脚本中的 `DISPLAY_DATE = datetime.now().strftime("%Y-%m")` 自动生成。本版页面显示为 `2026-05`。生成文件名仍使用 `RUN_DATE_SUFFIX = datetime.now().strftime("%Y%m%d")`，便于区分每次发布批次。

本地项目的过程文件统一收纳在根目录的 `process_files/` 下。脚本运行时会自动创建 `process_files/process_YYYYMMDD_local_assets/` 作为临时 HTML 和校验文件目录，避免每次生成都在项目根目录新增零散的 `process_*` 文件夹。

## 3. 数据处理思路

地图只依赖两个业务数据文件：

- `REITs_location_updating.xlsx`
- `location.csv`

Python 脚本先读取 `location.csv`，生成 `name -> longitude / latitude` 的坐标查找表，再根据 Excel 中的 `项目城市` 和 `项目省份` 自动匹配城市层与省份层经纬度。

当前底层资产字段采用新的维护格式：

```text
{城市1资产A,城市1资产B}|{城市2资产A}
```

解析规则是：

- 每个 `{}` 对应一个城市。
- 不同城市之间用 `|` 分隔。
- `{}` 内部保留该城市对应的底层资产列表。
- 城市顺序与 `项目城市` 字段保持一致。

脚本会据此生成三类核心结构：

- `province_data_pair`：省份层散点、数量和 tooltip 数据。
- `city_data_pair`：城市层散点、数量和 tooltip 数据。
- `asset_hierarchy_sorted`：右侧统计面板使用的“资产类型 -> REITs -> 城市 -> 底层资产”层级结构。

## 4. 地图渲染架构

当前地图采用“Python 生成 HTML + JavaScript 增强交互”的方式。

第一步，`reits_map.py` 使用 `pyecharts` 生成中国 Geo 地图骨架，并把临时 HTML 输出到 `process_files/process_YYYYMMDD_local_assets/`。

第二步，脚本向 HTML 中注入自定义 CSS、导航按钮、搜索框、右侧统计面板、缩放提示和交互脚本。

第三步，脚本把 `echarts.min.js` 和 `china.js` 直接内嵌到最终 HTML 中。这样 `index.html` 上传到 GitHub Pages 后，即使外部 CDN 访问不稳定，页面也能直接加载地图。

## 5. 双层视图设计

地图分为两套独立渲染配置：

- 全国 / 省份视图：展示各省份 REITs 项目数量，并保留省份散点标签。
- 城市视图：展示各城市 REITs 项目数量和城市名称。

二者通过缩放阈值切换：

- 小于阈值时，恢复为全国 / 省份视图。
- 大于等于阈值时，切换为城市视图。

这两套视图分别由独立 option 构建，而不是在同一套配置上反复增删 series。这样能避免之前出现过的几个问题：

- 缩小再放大后圆点消失。
- 标签颜色变淡。
- 省份 tooltip 退化成维度值。
- 图例、底部信息和当前视图状态不一致。

## 6. 页面交互模块

当前网页包含以下交互模块：

- 顶部区域导航：全国、京津冀、长三角、大湾区、成渝、长江中游。
- 当前视图提示：显示当前处于省份视图或城市视图。
- 搜索框：支持按 REITs 名称和底层资产搜索。
- 右侧统计面板：按资产类型、REITs、城市和底层资产逐层展开。
- tooltip：悬浮省份或城市圆点时显示对应项目明细。
- 底部标题：中国 REITs 分布。
- 底部制作信息：显示数据来源、原创制作和制作月份。

页面的核心体验是：首次打开即展示全国分布，放大后进入城市层，缩回后回到稳定的全国层。

## 7. 离线依赖与国内访问优化

当前版本保留本地化前端依赖处理：

- `echarts.min.js`
- `china.js`

`reits_map.py` 中维护了 `LOCAL_ASSET_FILES` 映射，生成 HTML 时会把这两个 JS 文件直接嵌入 HTML。这样最终 `index.html` 不再依赖 `assets.pyecharts.org`，更适合国内访问环境，也更适合 GitHub Pages 静态托管。

## 8. 发布到 GitHub Pages 的方式

GitHub Pages 使用仓库根目录的 `index.html` 作为站点入口。因此发布最新地图时，只需要保证：

- 根目录 `index.html` 是最新生成的 HTML。
- 根目录包含最新 `reits_map.py`。
- 根目录包含最新数据文件和依赖文件。
- README 和设计说明同步描述当前版本。
- 历史版本存入 `history/YYYYMMDD/`。

当前站点入口为：

```text
https://wqm12.github.io/C-REITs/
```

## 9. 维护建议

后续维护时建议遵循以下原则：

- 优先维护 `reits_map.py`，不要再以旧 notebook 作为主入口。
- 数据更新后，先运行脚本生成新的日期版 HTML，再同步为 GitHub 根目录 `index.html`。
- 每次大版本发布前，把当前线上版本先归档到 `history/YYYYMMDD/`。
- 保持 `REITs_location_updating.xlsx`、`location.csv`、`echarts.min.js`、`china.js` 与脚本同级，避免路径漂移。
- 过程文件统一放入 `process_files/`，不要再在项目根目录直接新增 `process_*` 文件夹；脚本已经通过 `PROCESS_ROOT = PROJECT_DIR / "process_files"` 自动适配。
- 如果只改数据，不改页面逻辑，通常只需要重新生成 HTML 并上传 `index.html` 与数据文件。
- 页面底部制作日期按月份自动更新，不需要手动改成具体日期。

2026-05-27 版本的核心设计是：用 `reits_map.py` 将更新后的 REITs 数据、经纬度底表和本地前端依赖打包成一个可直接访问的 GitHub Pages 静态网站，页面底部日期按月份自动生成，同时保留 2026-05-21、2026-05-06 与 2026-04-26 历史快照，方便后续追溯和维护。
